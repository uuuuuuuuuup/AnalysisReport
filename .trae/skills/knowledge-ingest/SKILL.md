# 知识归档 (knowledge-ingest)

## 触发规则

用户在对话中产生了有价值的分析内容后，说"存一下""归档""记下来""保存分析"等指令时触发。

适用场景：
- 龟龟策略分析报告生成后
- 和 AI 讨论某只股票得出了判断
- 读研报/财报后的感悟总结
- 任何关于股票、行业、投资主题的分析对话

## 核心定位

**不做重复存储，只存结构化摘要。** 如果分析原文是文件（如龟龟策略报告），SiYuan 只存摘要 + 引用链接，原文留在原地。

## 知识库目录结构

SiYuan 中维护以下目录（首次使用时自动创建）：

```
/投资知识库/
├── 📄 _索引.md                    # 总目录，自动维护
├── 📁 公司日志/
│   └── 📄 {code}_{name}.md        # 每家公司一篇，按时间线追加
├── 📁 行业洞察/
│   └── 📄 {行业名}.md             # 按 GICS/申万行业分类
├── 📁 主题研究/
│   └── 📄 {主题名}.md             # 跨行业的投资主题
└── 📁 风险跟踪/
    └── 📄 {风险类型}.md           # 持续跟踪的风险点
```

## 执行流程

### Step 1：理解上下文

从当前对话中识别：
- **涉及股票**：代码 + 名称
- **讨论主题**：行业、概念、宏观话题
- **核心结论**：评级判断、多空逻辑
- **关键数据**：ROE、PE、增长率等具体数字
- **风险点**：已知风险、不确定性
- **操作建议**：建仓/持有/减仓/观察

如果信息不完整（比如讨论了但没提代码），主动问用户补充。

### Step 2：结构化整理

将散乱的对话整理成以下结构：

```markdown
### YYYY-MM-DD | {来源标签}

- **判断**: {一句话核心结论}
- **逻辑**: {多空逻辑，2-4 条要点}
- **关键指标**: {具体数字}
- **风险**: {已知风险}
- **建议**: {操作方向}
- 📎 {如有原文报告，附链接}
```

来源标签示例：`龟龟策略-GLM5`、`AI对话分析`、`研报阅读`、`财报解读`

### Step 3：写入 SiYuan

使用 siyuan-sisyphus MCP 的 `fs` 工具操作文件。

#### 3a. 确保目录存在

先 `fs(action="ls", path="/投资知识库/")` 检查目录是否存在。
不存在则 `fs(action="write", path="/投资知识库/.gitkeep", markdown="")` 触发创建。

#### 3b. 写入公司日志

文件路径：`/投资知识库/公司日志/{code}_{name}.md`

- 若文件**不存在**：新建，写入标题 + 标签行 + 第一条分析记录
- 若文件**已存在**：用 `fs(action="replace")` 在 `## 分析记录` 标题后插入新条目（最新在上）

文件模板：
```markdown
# {name} ({code})

🏷️ #{行业1} #{行业2} #{概念标签}

## 分析记录

{按时间倒序的分析条目}
```

#### 3c. 写入/更新行业洞察

文件路径：`/投资知识库/行业洞察/{行业名}.md`

- 若文件**不存在**：新建，列出关联公司
- 若文件**已存在**：追加本次新观点，更新关联公司列表

格式：
```markdown
# {行业名}

## 关联公司
- [[../公司日志/{code}_{name}|{name}]] - {一句话定位}

## 分析记录

### YYYY-MM-DD
- {本次关于该行业的观点}
```

#### 3d. 写入/更新主题研究

文件路径：`/投资知识库/主题研究/{主题名}.md`

格式同行业洞察，但面向跨行业主题（如"高股息""消费降级""AI产业链"）。

#### 3e. 更新索引

`/投资知识库/_索引.md` 自动维护：

```markdown
# 投资知识库索引

> 最后更新: YYYY-MM-DD

## 公司覆盖
| 代码 | 名称 | 行业 | 最近评级 | 最近分析 |
|------|------|------|---------|---------|
| ... | ... | ... | ... | ... |

## 行业覆盖
- [[行业洞察/{行业名}|{行业名}]] ({N}家公司)

## 主题研究
- [[主题研究/{主题名}|{主题名}]]

## 风险跟踪
- [[风险跟踪/{风险名}|{风险名}]]
```

### Step 4：反馈

执行完毕后，简洁地告知用户：
- 更新/新建了哪些文档
- 关联了多少条已有笔记
- 提醒是否有信息缺失需要补充

## 注意事项

1. **宁缺毋滥**：如果对话内容没有实质性的分析结论（只是闲聊或数据查询），礼貌地告诉用户"这次对话好像没有需要归档的分析结论，等有判断的时候再存。"
2. **不覆盖原文**：如果是龟龟策略报告，只存摘要 + 链接，不要复制全文到 SiYuan。
3. **追加不覆盖**：同一只股票的新分析追加在旧分析前面，保留思考演变。
4. **标签使用 #tag# 格式**：SiYuan 的标签语法是 `#标签名#`。
5. **双向链接使用 `[[路径|显示名]]` 格式**：这是 SiYuan 的 wiki-link 语法。
6. **信息来源要标注**：每条分析记录标注来源（哪个模型、哪份研报、哪次对话），方便日后评估信息来源的可靠性。
