# 投资组合周报自动化系统设计文档

**日期**：2026-05-29  
**版本**：v1.0  
**状态**：待评审

---

## 1. 背景与目标

用户已持有274份基于"稳健投资策略"框架的深度分析报告，需要建立一套**自动化周报跟踪系统**，对重点关注的标的进行定期再分析。

### 核心目标
- 从274份报告中筛选出重点关注的标的池
- 每周对关注池执行轻量级再分析（股价、公告、研报、资金流向）
- 生成每家公司独立的周报文件（日期.md）
- 汇总所有周报生成合并报告并发送邮件

### 非目标
- 不替代原有的深度分析报告
- 不每周重跑完整四因子分析
- 不做预测性判断（仅做跟踪和信号检查）

---

## 2. 系统架构

采用**数据脚本 + Claude Code 分析 + 汇总智能体 + 邮件发送**的四层架构：

```
+-------------------+     +-------------------+     +-------------------+
|  Step 1: 数据收集  | --> |  Step 2: 周报生成  | --> |  Step 3: 汇总报告  |
|  fetch_weekly.py   |     |  Claude Code Skill |     |  Summary Agent    |
+-------------------+     +-------------------+     +-------------------+
                                                          |
                                                          v
                                                  +-------------------+
                                                  |  Step 4: 邮件发送  |
                                                  |  send_email.py    |
                                                  +-------------------+
```

### 数据流

1. **数据采集脚本**遍历 `每周复盘重点关注/` 下所有公司目录，调用 AI-Tools MCP 获取最新数据
2. 数据写入 `latest_data.json`（**覆盖式存储**，不保留历史版本）
3. **Claude Code** 读取 `latest_data.json` + 各公司原始分析报告，逐一生成周报
4. **汇总智能体**读取所有周报文件，生成合并汇总报告
5. **邮件脚本**读取汇总报告，通过 SMTP 发送

## 3. 组件详细设计

### 3.1 关注池管理

**目录结构**：
```
每周复盘重点关注/
├── 000513/                    # 丽珠集团
│   ├── 丽珠集团_稳健投资策略分析报告.md   # 原始深度报告（复制）
│   ├── data_pack_market.md              # 原始市场数据（复制）
│   ├── data_pack_report.md              # 原始深度数据（复制）
│   ├── 2026-05-22.md                    # 上周周报
│   └── 2026-05-29.md                    # 本周周报
├── 603529/                    # 爱玛科技
│   └── ...
└── ...
```

**筛选逻辑**（从274份报告中提取）：
1. 仓位建议为"可建仓/配置/观察"的标的
2. 当前股价低于目标买入价的标的优先
3. 正安全边际的标的优先
4. 排除明确"否决/不建仓"的标的

### 3.2 数据采集脚本（fetch_weekly_data.py）

**输入**：`每周复盘重点关注/*/` 所有目录

**输出**：`每周复盘重点关注/_weekly_data/latest_data.json`

**采集接口**（经测试验证可用）：

| 数据项 | MCP 工具 | 返回值 |
|:---|:---|:---|
| 最新股价 | `QueryStockPriceInfo` | currentPrice, changePercent |
| 公司公告 | `GetStockNotice` | title, noticeDate, columnName |
| 券商研报 | `GetStockResearchReport` | title, orgName, rating, content |
| 资金流向 | `GetStockMoneyFlowDetail` | mainInflow, superLargeInflow |
| 全市场新闻 | `GetSinaFinanceNews` | title, content, isRed |

**数据不足时的降级策略**：
- 当 MCP 接口返回空或失败时，记录 `error` 字段
- Claude Code 分析时可调用 `mx_finance_search` 或 `mx_financial_assistant` 补充搜索

**JSON 输出格式**：
```json
{
  "fetch_date": "2026-05-29",
  "fetch_time": "21:30:00",
  "macro_news": [
    {"title": "...", "content": "...", "isRed": true}
  ],
  "stocks": {
    "600519": {
      "name": "贵州茅台",
      "price": {"current": 1326.0, "change_pct": 3.92},
      "notices": [
        {"title": "...", "date": "2026-05-28", "type": "股本变动"}
      ],
      "reports": [
        {"title": "...", "orgName": "诚通证券", "rating": "强烈推荐"}
      ],
      "money_flow": {
        "mainInflow": 6361594192,
        "superLargeInflow": 2302213712
      },
      "error": null
    }
  }
}
```

**覆盖机制**：
- 固定文件名 `latest_data.json`
- 每次运行直接覆盖，不保留历史版本
- 如果某只股票采集失败，标记 `error` 字段，Claude Code 分析时处理

### 3.3 周报生成（Claude Code Skill）

**触发方式**：用户输入指令 `/weekly-review` 或手动启动

**输入**：
- `latest_data.json`（最新采集数据）
- `每周复盘重点关注/{code}/原始分析报告.md`

**输出**：`每周复盘重点关注/{code}/{date}.md`

**周报格式**：

```markdown
# {公司名}（{代码}）周报 — {日期}

## 一、本周股价
- 当前股价：¥{price}（周涨跌 {change_pct}%）
- 目标买入价：¥{target_price}（原始报告）
- 距离目标价：{distance}%（{ closer/farther }）

## 二、本周大事
### 公告
- {日期} | {类型} | {标题摘要}

### 研报
- {日期} | {机构} | {评级} | {核心观点摘要}

## 三、资金动向
- 主力资金净流入：{amount} 万元（{流入/流出}）
- 超大单净流入：{amount} 万元

## 四、风险信号检查
| 监控指标 | 原始报告阈值 | 当前状态 | 是否触发 |
|:---|:---|:---|:---:|
| 广义净现金 | >{阈值} | {当前} | {是/否} |
| FCF yield | >{门槛值} | {当前} | {是/否} |
| 营收增长 | 不大幅负增长 | {当前} | {是/否} |

## 五、与原始分析对比
- 精算穿透回报率：原始 {original}% → 当前 {current}%（股价变动导致）
- 安全边际：原始 {original} pct → 当前 {current} pct

## 六、本周结论
**信号**：{🟢 正常 / 🟡 关注 / 🔴 告警}

**核心判断**：{1-2句总结}

**操作建议**：{维持 / 加仓 / 减仓 / 清仓 / 进一步观察}

**需跟踪事项**：
1. {事项1}
2. {事项2}
```

**分析流程**：
1. 从目录名解析股票代码
2. 读取 `latest_data.json` 中该公司的数据
3. 读取原始分析报告，提取目标价、监控阈值、安全边际等
4. 对比分析：股价变化、公告重大性、研报评级变化、资金流向
5. 检查风险信号是否触发
6. 输出周报文件

**执行方式**：
- 30家公司串行分析（每家公司独立上下文）
- 每家公司分析约5-10分钟
- 全部完成后自动进入汇总阶段

### 3.4 汇总智能体

**触发时机**：30家公司周报全部生成后

**输入**：`每周复盘重点关注/*/{date}.md`

**输出**：`每周复盘重点关注/_summary/{date}_汇总报告.md`

**汇总报告结构**：

```markdown
# 投资组合周报汇总 — {日期}

## 一、本周市场概览
- 上证指数：{值}（{涨跌}%）
- 深证成指：{值}（{涨跌}%）
- 创业板指：{值}（{涨跌}%）

## 二、关注池表现
- 关注标的数：{N} 只
- 平均涨跌幅：{N}%
- 跑赢大盘：{N} 只 | 跑输大盘：{N} 只

## 三、信号统计
| 信号 | 数量 | 标的 |
|:---|:---:|:---|
| 🟢 正常 | {N} | {代码列表} |
| 🟡 关注 | {N} | {代码列表} |
| 🔴 告警 | {N} | {代码列表} |

## 四、本周重点事件
1. **{公司名}**：{事件描述}
2. **{公司名}**：{事件描述}

## 五、操作建议
### 可建仓/加仓
- {代码} {名称}：{理由}

### 需减仓/清仓
- {代码} {名称}：{理由}

### 继续观察
- {代码列表}

## 六、下周跟踪清单
- {事项1}
- {事项2}
```

### 3.5 邮件发送脚本（send_email.py）

**输入**：`每周复盘重点关注/_summary/{date}_汇总报告.md`

## 4. 执行流程

### 4.1 首次运行

```bash
# 1. 创建目录结构
mkdir -p 每周复盘重点关注/_weekly_data
mkdir -p 每周复盘重点关注/_summary
mkdir -p 每周复盘重点关注/scripts

# 2. 从274份报告中筛选关注池并复制
python3 scripts/filter_watchlist.py

# 3. 采集最新数据
python3 scripts/fetch_weekly_data.py

# 4. 在 Claude Code 中运行周报生成（手动触发）
# 用户输入：/weekly-review

# 5. 生成汇总报告
# Claude Code 自动执行

# 6. 发送邮件
python3 scripts/send_email.py 2026-05-29
```

### 4.2 每周例行运行

```bash
# Step 1: 采集数据（约5-10分钟）
python3 scripts/fetch_weekly_data.py

# Step 2-4: 在 Claude Code 中执行（约2-3小时）
# 用户输入：/weekly-review
# Claude Code 自动生成30份周报 + 汇总报告

# Step 5: 发送邮件
python3 scripts/send_email.py 2026-05-29
```

## 5. 错误处理

| 异常情况 | 处理方式 |
|:---|:---|
| 某只股票数据采集失败 | 标记 `error`，周报中标注"数据缺失"，不阻塞其他公司 |
| MCP 接口限流 | 增加 1-3 秒延迟，重试 3 次 |
| 某家公司周报生成失败 | 记录错误日志，继续下一家 |
| SMTP 发送失败 | 打印错误信息，用户可手动发送文件 |
| 原始分析报告缺失 | 跳过该公司，记录到日志 |
