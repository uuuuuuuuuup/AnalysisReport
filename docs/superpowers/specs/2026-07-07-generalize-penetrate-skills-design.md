# 穿透财报与叙事分析 Skill 通用化设计文档

- 日期：2026-07-07
- 状态：已确认，待实现
- 作者：Claude Code + 用户

---

## 1. 背景与问题

现有两个 skill：

- `penetrate-narrative-stock-analysis`：基于 DCF 反算的公司叙事定价/估值分析框架。
- `penetrate-financial-report`：在 narrative 基础上叠加三张表（资产负债表、利润表、现金流量表）深度验证。

当前问题：

1. `scripts/generate_report.py`（narrative 版）完全硬编码为「中际旭创 300308」案例。
2. `scripts/generate_report.py`（financial 版）是占位符模板，所有数据为 `___`，无法分析任意公司。
3. 两个 skill 触发词冲突（都响应「分析某公司」）。
4. 数据源未统一，依赖 Wind/iFind/同花顺等未集成的数据。

本设计目标：让两个 skill 能够分析**任意 A 股公司**，数据自动获取，保留原有分析框架和报告结构。

---

## 2. 目标与非目标

### 2.1 目标

- 支持任意 A 股公司的 narrative 分析。
- 支持任意 A 股公司的 financial 财报深度分析。
- Financial skill 可独立运行，内部调用 Narrative Agent 获取 DCF 前置数据。
- Narrative skill 独立运行，不感知 Financial skill 的存在。
- 统一数据获取层，优先使用项目内已有 skill（mx-*、gtht-lingxi-unified），AI-Tools 兜底。
- 默认输出 **Markdown + 图片**，可选生成 **Word / HTML**。
- 报告结构、章节、标题层级与现有 Word/HTML 报告保持一致。

### 2.2 非目标

- 本阶段不支持港股/美股（H 股扩展作为后续迭代）。
- 不合并两个 skill 为一个 skill，也不新建 orchestrator skill。
- 不用于维护现有网站，但保留可选 HTML 输出能力。

---

## 3. 整体架构

保留两个独立 skill：

```
用户
 ├─ 触发 "分析[公司]" → penetrate-narrative-stock-analysis
 │   └─ 独立运行：数据获取 → DCF 反算 → 阶段判断 → 叙事概率 → 护城河 → 投资建议
 │   └─ 输出：Markdown 报告 + 图片（可选 Word / HTML）
 │
 └─ 触发 "穿透财报[公司]" → penetrate-financial-report
     ├─ 数据获取层：公司代码、股价、市值、股本、E0/E1/E2/E3、三张表
     ├─ 派 Narrative 子 Agent：传入数据，返回 DCF 结果与叙事结论（结构化 Markdown）
     ├─ 财报分析层：资产负债表、利润表、现金流量表逐项分析
     ├─ 验证层：叙事预期 vs 财报现实对比
     └─ 输出：Markdown 报告 + 图片（可选 Word / HTML）
```

关键原则：Narrative skill 不知道自己被 Financial 调用；Financial 通过调用 Narrative 子 Agent 复用 DCF 和叙事逻辑，而不是直接 copy 代码。

---

## 4. Skill 边界与职责

### 4.1 Narrative Skill

**职责**：

- 接受公司代码/名称 + 股价、市值、股本、E0/E1/E2/E3、行业数据等输入。
- 执行 DCF 反算（三档折现率 8%/10%/12%）。
- 做产业空间测算、阶段判断、叙事变化概率、护城河、投资建议。
- 生成 Markdown 报告 + 图片，可选 Word / HTML。
- 当被 Financial Agent 调用时，进入「Financial 支持模式」，使用传入数据，只返回 DCF 结果和关键叙事结论（结构化 Markdown），不重新获取数据。

**不依赖 Financial**：独立运行。

### 4.2 Financial Skill

**职责**：

- 接受公司代码/名称。
- 收集数据：股价、股本、一致预期、三张表、行业背景。
- 调用 Narrative 子 Agent 获取 DCF 结果和叙事结论。
- 获取完整三张表，按科目逐项分析。
- 用 DCF 结果做「叙事预期 vs 财报现实」对比。
- 生成 Markdown 报告 + 图片，可选 Word / HTML。

**依赖 Narrative**：仅依赖 DCF 计算结果和关键叙事结论，不依赖完整 narrative 文字报告。

## 5. 数据获取策略

### 5.1 数据源优先级

| 优先级 | 来源 | 用途 |
|--------|------|------|
| P1 | `mx-data`（东财） | 财务指标、可比公司、营收/利润等结构化数据 |
| P2 | `gtht-lingxi-unified`（国泰海通灵犀） | 实时行情、总市值、研报、财务数据 |
| P3 | `mcp__AI_Tools` | 三张表、K 线、公告等兜底 |
| P4 | Web Search / 用户输入 | 行业 TAM、券商目标价、缺失数据 |

### 5.2 各数据项获取路径

| 数据项 | 优先来源 | 说明 |
|--------|---------|------|
| 股价、总市值、换手率 | `gtht-lingxi-unified marketdata` | 实时行情 |
| 营收、净利润、毛利率、ROE | `mx-data` 或 `gtht-lingxi-unified financial` | 自然语言查询 |
| E0/E1/E2/E3 一致预期 | `gtht-lingxi-unified research`（研报）+ `mx-data` | 可能缺失，需搜索/用户补 |
| 行业 TAM / 市场份额 | Web Search + 研报解析 | 主观性高，需标注来源 |
| 券商目标价 | `gtht-lingxi-unified research` | 研报解析 |
| 完整三张表 | `mcp__AI_Tools`（GetBalanceSheet 等） | 兜底 |
| 历史 K 线 | `mcp__AI_Tools` 或 `gtht-lingxi-unified` | 阶段判断 |
| 公司公告 | `mcp__AI_Tools` | 业绩快报、投资者关系 |

### 5.3 缺失数据处理

1. 高置信度数据（股价、财务指标）：优先工具，拿不到时告警并询问用户。
2. 主观/预测数据（E1/E2/E3、行业 TAM）：工具拿不到时，用 Web Search 搜索公开数据，并标注不确定性；仍缺失则问用户。
3. 关键缺失：如果 E0/E1/E2/E3 完全缺失，无法跑 DCF，必须暂停并问用户补充。

## 6. Narrative 与 Financial 之间的数据契约

### 6.1 传输格式：结构化 Markdown

Agent 间通信不使用 JSON，使用 Markdown 分段 + 表格，更紧凑、更适合 LLM 读取。

### 6.2 Financial 传给 Narrative Agent 的输入

```markdown
## 任务
为 financial 财报分析提供 narrative DCF 与叙事结论。

## 公司信息
- 公司：中际旭创
- 代码：300308.SZ
- 基准日：2026-06-26
- 市值：13,900 亿元
- 总股本：11.15 亿股
- 当前股价：1,247 元
- E0：107.97 亿
- E1：299.76 亿
- E2：520.88 亿
- E3：766.80 亿
- 行业：光模块

## 模式
- mode: `financial-support`
- 说明：不重新获取数据，不生成完整报告，只返回 DCF 结果和关键叙事结论。
```

### 6.3 Narrative Agent 返回给 Financial 的输出

```markdown
## DCF 反算结果
| 折现率 r | 隐含 L(亿元) | L/E3 | L/E0 | 隐含增速 g |
|---------|-------------|------|------|-----------|
| 8% | 1,356.4 | 1.77x | 12.56x | 12.1% |
| 10% | 1,900.0 | 2.48x | 17.60x | 19.9% |
| 12% | 2,556.7 | 3.33x | 23.68x | 27.2% |

## 叙事判断
- 分级：极高增长（透支风险大）
- 阶段：流动性冲击期末段→回调期
- 上修概率：15% | 维持：35% | 下修：35% | 深度下修：15%

## 产业空间情景
| 情景 | TAM(亿美元) | 份额 | 净利率 | 终局 L(亿) |
|-----|------------|------|-------|-----------|
| 保守 | 600 | 30% | 30% | 389 |
| 基准 | 900 | 35% | 32% | 726 |
| 乐观 | 1,300 | 40% | 35% | 1,310 |
| 极乐 | 1,800 | 40% | 38% | 1,970 |

## 护城河与风险
- 护城河：光模块龙头，规模效应显著，但 CPO 替代风险上升
- 关键风险：产能过剩、CPO 技术替代、北美客户集中
```

## 7. 报告生成格式

### 7.1 默认输出

- 格式：Markdown（`.md`）+ 图表图片（`.png`）
- 目录结构：

```
reports/
└── 中际旭创_300308/
    ├── 中际旭创_穿透叙事分析报告.md
    ├── 中际旭创_穿透财报分析报告.md
    ├── dcf_sensitivity.png
    ├── revenue_profit_trend.png
    └── balance_sheet_key_items.png
```

### 7.2 可选输出

通过参数触发：

```bash
python scripts/generate_report.py --company 中际旭创 --format docx
python scripts/generate_report.py --company 中际旭创 --format html
```

### 7.3 Markdown 结构要求

- 内容结构、章节顺序、标题层级与现有 Word/HTML 报告 100% 一致。
- 表格转换为 Markdown 表格。
- 引用块转换为 Markdown 引用块（`> ...`）。
- 图表用 `![图 x-x：标题](图片路径)` 替代。
- 强调/标红用文字描述或 Markdown 加粗替代。

### 7.4 图表生成

- 使用 Python matplotlib 生成 PNG。
- 配色遵循中国股市惯例：上涨红色、下跌绿色；公司数据红色柱、行业均值绿色柱、趋势线蓝色。

## 8. 错误处理与数据质量

### 8.1 数据质量红线

| 校验项 | 规则 | 失败处理 |
|--------|------|---------|
| 市值自洽 | 股价 × 总股本 = 总市值，误差 < 5% | 标红告警，优先用工具数据，不一致时问用户 |
| 单位换算 | 所有金额统一为亿元（/1e8），禁止 /1e9 | 自动转换，异常时告警 |
| DCF 反算校验 | 反算 L 正算回市值，误差 < 5% | 未通过则重新计算 |
| 一致预期异常 | E1 > 当年营收 × 历史最高净利率 | 标红告警，请用户复核 |
| 季度同季对比 | Q1 比 Q1，Q2 比 Q2 | 自动匹配，跨季则报错 |
| 三张表联动 | 利润表变化在资产负债表/现金流量表找对应 | 不匹配时标注说明 |
| 子项收入交叉验证 | 情景表分项收入 ≤ 总营收 | 触发告警，修正市占率 |
| 市占率合理性 | 保守情景市占率不应大幅高于当前实际 | 不合理时告警 |

### 8.2 错误处理策略

| 场景 | 处理 |
|------|------|
| 数据工具调用失败 | 切换下一优先级数据源；全部失败则问用户 |
| 关键数据缺失（E0/E1/E2/E3） | 暂停分析，询问用户补充 |
| 非关键数据缺失（行业 TAM、券商目标价） | 用搜索补，标注不确定性；仍缺失则简化该章节 |
| Narrative Agent 失败 | 本地调用 DCF 脚本回退，跳过阶段/概率分析 |
| 数据不一致 | 标红告警，用最新工具数据，让用户确认 |
| 输出格式转换失败 | 默认保留 Markdown，报告可用 |

### 8.3 用户交互

数据缺失时，用自然语言询问用户，例如：

> 未找到 中际旭创 的 2027-2028 年一致预期净利润，请提供 E2、E3（亿元），或告诉我是否跳过该部分？

## 9. 测试策略

### 9.1 单元测试

| 模块 | 测试内容 |
|------|---------|
| `dcf_implied.py` | 已知输入下的 L 计算、正算反算误差 < 5% |
| 数据获取层 | 用 3-5 只不同行业股票测试各数据源返回值 |
| Markdown 生成器 | 表格、图片引用、标题层级正确 |
| 财报标准化 | 资产负债表/利润表科目解析 |

### 9.2 集成测试

| 场景 | 测试目标 |
|------|---------|
| 单独跑 Narrative | 输入任意公司，验证 Markdown 结构完整 |
| 单独跑 Financial | 输入任意公司，验证能调用本地 DCF 回退 |
| Financial 调用 Narrative Agent | 验证 Agent 返回格式可被解析 |
| 数据缺失场景 | 正确提示用户，不崩溃 |
| 不同行业公司 | 消费、科技、金融、周期各选 1 只测试通用性 |

### 9.3 验证清单

- [ ] 标题层级正确
- [ ] Markdown 表格格式正确
- [ ] 图片引用路径存在
- [ ] DCF 反算与正算误差 < 5%
- [ ] 所有金额单位统一为亿元
- [ ] 总市值 = 股价 × 总股本
- [ ] 叙事 vs 财报对比章节已填充
- [ ] 免责声明存在

## 10. 未来扩展（本阶段不做）

- **港股支持**：增加汇率换算、IFRS 科目映射、fiscal year 处理。
- **美股支持**：接入 10-K/10-Q 数据，适配 GAAP 科目。
- **统一 Orchestrator**：如果后续需要更多分析维度（行业研究、事件驱动），可考虑新建 orchestrator skill。
- **PDF 输出**：可选支持 PDF 导出。

## 11. 决策记录

| 决策 | 选择 | 原因 |
|------|------|------|
| 市场范围 | 先 A 股 | 当前框架和数据源均围绕 A 股，港股/美股后续扩展 |
| 入口设计 | 两个独立 skill | Narrative 独立，Financial 内部调用 Narrative Agent |
| 输出格式 | Markdown 默认，Word/HTML 可选 | 版本控制友好，且保留分享能力 |
| 数据源优先级 | mx-* → gtht-lingxi-unified → AI-Tools | 优先使用项目内已有 skill |
| Agent 数据格式 | 结构化 Markdown | 比 JSON 紧凑，比纯自然语言可靠 |
| Narrative 被调用时 | Financial 支持模式 | 不重新获取数据，只跑 DCF 和关键叙事分析 |
