# AI 对话管理与上下文召回系统 — 设计文档

> 本文档用于梳理当前痛点与可行方案，作为后续开发决策的参考。
>
> 状态：思路梳理 | 日期：2026-06-04

***

## 一、当前痛点

### 1.1 核心问题：移动端依赖厂商 App，对话历史无法统一管理

| 场景    | 现状                                | 带来的问题                         |
| ----- | --------------------------------- | ----------------------------- |
| 投资分析  | 在 DeepSeek App 里聊股票，对话记录存在厂商服务器   | 无法导出、无法分类、无法让 AI "记住" 之前的分析结论 |
| 日常咨询  | 在多个平台（DeepSeek、Claude、ChatGPT）间切换 | 历史散落各处，同一个问题可能重复问             |
| 移动端使用 | 必须使用厂商提供的 App 或网页                 | 没有自己的数据主权，上下文管理完全受限           |

### 1.2 具体表现

**痛点 1：每次新对话都要重复背景**

- 例：上周分析了 "110 万资产配置"，本周想追问 "现在进场时机到了吗？"
- 结果：必须手动复述持仓、策略、之前的结论，否则 AI 完全失忆

**痛点 2：完整对话太长，无法直接发回给 AI**

- 例：一段投资咨询对话可能有 3 万字
- 结果：直接复制粘贴会浪费大量 token，也超过上下文长度限制

**痛点 3：历史对话无法有效检索和利用**

- 例：两个月前讨论过 "万科 A"，现在忘了具体结论
- 结果：只能在各平台里翻记录，费时费力

**痛点 4：移动端没有自主方案**

- 想要自己管理对话 → 只能在电脑上操作
- 手机端只能用厂商 App → 无法自定义上下文加载策略

## 二、约束条件

| 约束     | 说明                | 影响              |
| ------ | ----------------- | --------------- |
| 移动端刚需  | 必须在手机上能用          | 排除纯桌面端方案        |
| 低成本优先  | 月成本尽量控制在 ¥10 以内   | 优先无服务器架构        |
| 投资分析为主 | 对话需要长期跟踪、累积       | 上下文管理是核心，不是可有可无 |
| 日常咨询为辅 | 碎片化、轻量            | 不需要太复杂的分类和检索    |
| 未来可扩展  | 可能接入微信/飞书         | 架构需要预留扩展点       |
| 不兼容历史  | 现有厂商 App 的对话不需要导出 | 新系统从零开始         |

## 三、方案对比

### 3.1 方案 A：纯本地 PWA（最低成本）

**架构**：

```
手机浏览器 → NextChat (PWA) → IndexedDB (本地存储)
                              → 调用 DeepSeek API
```

**优点**：

- 零服务器成本
- 5 分钟部署（Cloudflare Pages / Vercel）
- 立刻能用

**缺点**：

- 换设备需手动导出/导入 JSON
- 无自动同步
- 上下文管理靠手动复制摘要

**适用**：验证需求阶段，个人单设备使用

***

### 3.2 方案 B：PWA + OSS 同步（⭐ 推荐）

**架构**：

```
手机 A (PWA)                  阿里云 OSS                  手机 B (PWA)
   │                          ┌─────────┐                    │
   │  1. 对话结束              │         │  3. 打开时下载      │
   │  → 压缩摘要               │摘要文件   │  → 历史索引        │
   │  → 上传 OSS               │索引清单   │  → 按需加载摘要     │
   │ ───────────────────────> │         │ ─────────────────> │
   │                          └─────────┘                    │
   │  2. 新对话开始时           ↑                            │
   │  → 查询本地索引            │                            │
   │  → 拼接相关摘要背景 ────────┘                            │
   │  → 发送给 DeepSeek API                                  │
```

**优点**：

- 月成本 ¥0-1（OSS 存储费几乎为零）
- 多端自动同步
- 上下文自动加载（根据标签/关键词匹配相关历史摘要）
- 数据主权在自己手里

**缺点**：

- 需要改造 NextChat 前端（增加 OSS 上传/下载模块）
- 需要设计摘要压缩策略

**适用**：个人长期使用，投资分析场景

***

### 3.3 方案 C：微信机器人 + OSS（最自然）

**架构**：

```
用户微信 → 微信服务器 → 阿里云函数 → 查询 OSS 历史
                                      ↓
                                  拼接 prompt
                                      ↓
                                  调用 DeepSeek API
                                      ↓
                                  返回结果 → 微信服务器 → 用户
```

**优点**：

- 不用打开浏览器，最符合现有习惯
- 消息推送自然

**缺点**：

- 需要云函数（有代码复杂度和调试成本）
- 微信接口有限制（消息长度、响应时间）
- 不适合长文本投资分析

**适用**：日常轻量咨询，不适合深度投资分析

## 四、推荐方案：方案 B（PWA + OSS）详细设计

### 4.1 数据流

```
[对话产生]
   │
   ▼
[前端 PWA]
   │
   ├── 完整对话 → IndexedDB（本地存档）
   │
   ├── 触发摘要生成（本地规则提取 / 调用 API）
   │       │
   │       ▼
   ├── 结构化摘要（JSON，见 4.2 格式）
   │       │
   │       ▼
   └── 上传 OSS（文件名：summaries/YYYYMMDD_HHMMSS_标题.json）
           │
           ▼
   更新索引文件（index.json）→ 上传 OSS
```

```
[新对话开始]
   │
   ▼
[前端 PWA]
   │
   ├── 下载 OSS index.json（历史索引）
   │       │
   │       ▼
   ├── 用户选择 / 自动匹配相关历史
   │       │
   │       ▼
   ├── 下载对应摘要文件
   │       │
   │       ▼
   ├── 拼接 system prompt：
   │    "你是价值投资顾问...
   │     【历史背景摘要】...（加载相关摘要）
   │     【本次问题】..."
   │       │
   │       ▼
   └── 发送给 DeepSeek API
```

### 4.2 摘要文件格式

```json
{
  "id": "conv_20260604_134638",
  "created_at": "2026-06-04T13:46:38",
  "updated_at": "2026-06-04T13:46:38",
  "title": "巴菲特式投资组合诊断",
  "tags": ["投资策略", "仓位管理", "牛市防御", "110万资产"],
  "model": "deepseek-chat",
  "token_estimate": 180,
  "one_liner": "110万资产配置诊断，建议降低高波动标的占比，等熊市信号再进场",
  "background": "总资产110万：100万短融ETF（511360）防守，10万进攻账户（高分红底仓5.6万 + 灵活仓位4.3万）",
  "key_conclusions": [
    "省广集团+华力创通占比偏高，建议降至总仓位5%以内",
    "熊市进场信号：沪深300 PE<12倍 + 破净股比例>10%",
    "心态属于'幸存者优先'，需警惕过度保守导致错失机会"
  ],
  "action_items": [
    "观察沪深300 PE和破净股比例，准备100万资金分批进场",
    "考虑将省广集团/华力创通减仓或止盈"
  ]
}
```

### 4.3 索引文件格式（index.json）

```json
{
  "version": "1.0",
  "updated_at": "2026-06-04T13:46:38",
  "conversations": [
    {
      "id": "conv_20260604_134638",
      "title": "巴菲特式投资组合诊断",
      "date": "2026-06-04",
      "tags": ["投资策略", "仓位管理", "牛市防御"],
      "one_liner": "110万资产配置诊断，建议降低高波动标的占比...",
      "token_estimate": 180
    }
  ],
  "tags_index": {
    "投资策略": ["conv_20260604_134638"],
    "仓位管理": ["conv_20260604_134638"]
  }
}
```

### 4.4 摘要生成策略

| 策略          | 方式                      | 成本          | 适用     |
| ----------- | ----------------------- | ----------- | ------ |
| **AI 自动摘要** | 调用 DeepSeek API 生成结构化摘要 | 每次 \~0.01 元 | 推荐，质量高 |
| **规则提取**    | 本地关键词匹配提取结论             | 免费          | 备用，速度快 |

**建议**：默认用 AI 摘要，网络不好时降级为规则提取。

### 4.5 上下文加载策略

```
新对话 system prompt 拼接逻辑：

1. 基础角色定义（~200 tokens）
   "你是价值投资顾问，熟悉四因子分析框架..."

2. 相关历史摘要（~300 tokens）
   根据用户输入的关键词 / 标签匹配最近 3 条相关对话摘要

3. 用户当前输入

总上下文控制在 ~1000 tokens 以内，避免浪费。
```

## 五、实施路径

### Phase 1：基础 PWA（验证需求）

**目标**：能聊、能存、能导出

| 任务              | 说明                    |
| --------------- | --------------------- |
| 部署 NextChat     | Cloudflare Pages 一键部署 |
| 配置 DeepSeek API | 填入 API key            |
| 测试对话            | 验证投资分析场景是否流畅          |
| 导出测试            | 手动导出 JSON，验证数据完整性     |

**时间**：1 天
**成本**：¥0

***

### Phase 2：摘要系统（核心能力）

**目标**：自动压缩对话，生成结构化摘要

| 任务     | 说明                                   |
| ------ | ------------------------------------ |
| 摘要生成脚本 | Python 脚本：读取对话 → 调用 API → 输出结构化 JSON |
| 索引管理   | 维护 index.json，支持按标签检索                |
| 摘要质量评估 | 对比原文和摘要，确保关键信息不丢失                    |

**时间**：2-3 天
**成本**：API 调用费（可忽略）

***

### Phase 3：OSS 同步（多端可用）

**目标**：多设备自动同步历史摘要

| 任务     | 说明                     |
| ------ | ---------------------- |
| OSS 配置 | 阿里云 OSS 创建 bucket，配置权限 |
| 上传模块   | 对话结束后自动上传摘要 + 更新索引     |
| 下载模块   | 打开 PWA 时自动下载最新索引       |
| 冲突处理   | 简单策略：时间戳较新的覆盖旧的        |

**时间**：2 天
**成本**：¥0-1/月

***

### Phase 4：智能上下文加载（体验优化）

**目标**：新对话自动携带相关历史

| 任务    | 说明                      |
| ----- | ----------------------- |
| 关键词匹配 | 根据用户输入匹配相关历史标签          |
| 摘要拼接  | 自动将相关摘要拼入 system prompt |
| 手动选择  | 支持用户手动勾选要加载的历史          |

**时间**：2 天
**成本**：¥0

***

### Phase 5：微信机器人（可选扩展）

**目标**：在微信里也能聊，共用同一套 OSS 数据

| 任务    | 说明                    |
| ----- | --------------------- |
| 云函数部署 | 阿里云函数计算接收微信消息         |
| 历史查询  | 从 OSS 读取相关摘要          |
| 消息回复  | 调用 DeepSeek API 后返回结果 |

**时间**：3-5 天
**成本**：¥0-5/月（云函数免费额度通常够用）

## 七、风险与备选

| 风险                   | 影响        | 备选方案                         |
| -------------------- | --------- | ---------------------------- |
| DeepSeek API 调整价格/政策 | 成本上升      | 随时可切换 Claude / OpenAI / 本地模型 |
| OSS 访问不稳定            | 同步失败      | 本地 IndexedDB 兜底，网络恢复后重试      |
| 摘要质量不稳定              | AI 遗漏关键结论 | 摘要生成后人工快速校对，逐步优化 prompt      |
| PWA iOS 限制           | 后台同步受限    | 改为"打开时主动同步"，非实时也能接受          |

***

## 八、后续可扩展方向

1. **向量检索**：历史多了之后，用 embedding 做语义搜索（而不仅是标签匹配）
2. **本地模型**：如果对话敏感，可切换到本地运行的小模型做摘要
3. **多模型支持**：同时支持 DeepSeek、Claude、Gemini，自动选择最合适的
4. **报表生成**：按月度/季度汇总投资分析结论，生成复盘报告
5. **自动化监控**：结合股票数据接口，当达到某个条件时主动推送提醒

| 检查点        | 问题               | 通过标准                      |
| ---------- | ---------------- | ------------------------- |

| Phase 4 结束 | 自动上下文加载是否有用？     | 新对话不需要手动复述背景              |
