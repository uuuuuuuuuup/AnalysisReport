# 关联发现引擎 (knowledge-discover)

## 核心定位

不分析新的外部信息，只**挖掘已有知识之间的隐藏关系**。前面两个 Skill（ingest、radar）负责把信息存进来，discover 负责让存进来的知识产生复利。

## 触发方式

- **定时**：每周一次（建议周六，radar 周报之后）
- **手动**：用户说"发现洞察""扫描关联"

## 三步执行法

```
Step 1: 结构化提取     →  把散乱 Markdown → 结构化矩阵
Step 2: 交叉比对       →  补全 wiki-link 漏掉的隐性关联
Step 3: 生成洞察       →  基于矩阵 + 比对结果 → 五种发现
```

---

## Step 1：结构化提取

### 目标
把 `/投资知识库/公司日志/` 下所有公司的 Markdown 文档，提取为一张内存中的分析矩阵。**不读原始全文，只提取结构化字段。**

### 提取字段

使用 `fs(action="read")` 逐篇读取每篇公司日志（不需要读完，读到关键信息即可）：

| 提取字段 | 来源（文档内标记） | 格式 |
|---------|-------------------|------|
| `code` | 文档标题中的代码 | `000002` |
| `name` | 文档标题中的名称 | `万科A` |
| `industry` | 文档开头的 `🏷️` 标签 | `["房地产", "央企"]` |
| `current_rating` | 最上面（最新）一条分析记录 | `exclude/warning/good` |
| `rating_trend` | 最近 3 条记录的评级序列 | `→→↗→→↘` 趋势箭头 |
| `bull_thesis` | 最新分析中的"逻辑"要点 | `["行业龙头", "低估值"]` |
| `key_risks` | 最新分析中的"风险" | `["需求萎缩", "融资成本高"]` |
| `implicit_premise` | 判断成立的关键假设（推断） | `["政策不会更严"]` |
| `last_analysis_date` | 最新记录的时间戳 | `2026-07-05` |
| `analysis_count` | 分析记录总条数 | `5` |
| `linked_companies` | wiki-link 链接到哪些公司 | `["600048_保利发展"]` |

### 提取方法

```
对于每篇公司日志 markdown：
1. 标题行提取 code + name（正则: # (.+) \((\d{6})\)）
2. 🏷️ 行提取 industry（正则: #(\S+)# → 提取标签文本）
3. 在 "## 分析记录" 下找到第一个 "### YYYY-MM-DD" → 提取最新分析
4. 从最新分析中提取 rating、bull_thesis、key_risks
5. 扫描全文所有 `[[../公司日志/` → 提取 linked_companies
6. 推断 implicit_premise：从 bull_thesis 反向推断（如"龙头低位"的前提是"行业不会消亡"）
```

### 输出
在 AI 上下文内存中构建分析矩阵（不落盘），格式如：

```
| # | 公司 | 评级 | 趋势 | 多头逻辑 | 风险 | 隐含前提 | 上次分析 | 关联公司 |
|---|------|------|------|---------|------|---------|---------|---------|
| 1 | 万科A(000002) | ❌ | →→ | 龙头,低PB | 需求萎缩,融资 | 政策不更严 | 0705 | 保利 |
| 2 | 茅台(600519) | ✅ | ↗ | 品牌壁垒 | 政策风险 | 消费不崩 | 0615 | - |
| 3 | ... | ... | ... | ... | ... | ... | ... | ... |
```

## Step 2：交叉比对

基于矩阵，用 SiYuan search 工具补充 wiki-link 漏掉的隐性关联。

### 2a. 标签共现检查

对矩阵中每个行业/概念标签，搜索 SiYuan 中打了相同标签但 `linked_companies` 中缺失的文档：

```
用 search(action="fulltext", query="#房地产#") 搜索
→ 找出所有打了 #房地产# 的文档
→ 对比矩阵中每个公司的 linked_companies
→ 应该互链但没互链的 → 记录为"遗漏关联"
```

### 2b. 风险重叠检查

对矩阵中出现的每个风险词（出现 ≥2 次），全文搜索：

```
用 search(action="fulltext", query="产能过剩") 搜索
→ 看哪些公司的文档里都提到了这个词
→ 聚合 → 组合层面的风险暴露
```

### 2c. 逻辑同源检查

对矩阵中"多头逻辑"列频繁出现的概念做搜索：

```
用 search(action="fulltext", query="消费降级") 搜索
→ 找出所有基于"消费降级"做判断的公司
→ 如果这个前提出问题，哪些公司的判断会同时失效？
```

### 2d. 信息新鲜度检查

```
对矩阵中 last_analysis_date 列：
→ 距今 > 90 天的 → 标记为"信号可能过期"
→ 距今 > 180 天的 → 标记为"信号严重过期，建议重新分析"
```

### 2e. 行业覆盖检查

```
矩阵中所有行业 vs 申万一级行业（31个）：
→ 哪些行业完全没覆盖？
→ 缺失是主动回避（你了解但不投）还是盲区（你没看过）？
→ 标记为"信息盲区"供用户判断
```

## Step 3：生成洞察

基于矩阵（Step 1）+ 比对结果（Step 2），生成五类发现。

### 发现 1：隐藏关联 🔗

**分析方式**：
- 对比矩阵中"多头逻辑"列 → 找出逻辑相似但没互链的公司对
- 对比矩阵中"风险"列 → 找出面临相同风险但没互链的公司对
- 交叉比对 2a 的遗漏关联结果

**输出格式**：
```markdown
### 🔗 隐藏关联

**万科A ↔ 保利发展**
- 共同逻辑：都是央企地产龙头，估值处于历史低位
- 共同风险：行业需求萎缩、融资成本上升
- 差异点：万科更激进（拿地更多），保利更保守
- 当前未互链，建议建立关联
- 证据：[[公司日志/000002_万科A]] + [[公司日志/600048_保利发展]]
```

### 发现 2：矛盾检测 ⚡

**分析方式**：
- 同一家公司：评级趋势列 + 多头逻辑列 → 逻辑变了但评级没变？
- 跨公司：公司 A 的看多逻辑和公司 B 的看空逻辑是否指向同一个宏观假设、但方向相反？

**输出格式**：
```markdown
### ⚡ 矛盾检测

**逻辑冲突：对"消费"的两种判断**
- 茅台(✅)：看多逻辑包含"消费韧性"
- 某消费股(❌)：看空逻辑包含"消费降级"
- 冲突：这两条假设不能同时成立。需要明确你对消费趋势的真实判断。
- 证据：[[公司日志/600519_贵州茅台]](2026-06-15) + [[公司日志/XXX]](2026-06-01)
```

### 发现 3：风险共振 ⚠️

**分析方式**：
- 聚合矩阵中"风险"列 → 任一风险词出现 ≥3 次
- 交叉比对 2b 的结果
- 计算：如果该风险同时爆发，持仓中几家公司受冲击？

**输出格式**：
```markdown
### ⚠️ 风险共振：对"政策"的集中暴露

以下 4 家公司的核心风险都依赖政策变量：
1. 万科A - 房地产政策
2. 招商蛇口 - 房地产政策
3. 保利发展 - 房地产政策
4. 某银行 - 金融监管政策

→ 如果政策方向不利，这 4 家可能同时承压，组合没有对冲。
→ 建议：考虑是否加入与政策弱相关的标的分散风险。
```

### 发现 4：判断漂移 📈

**分析方式**：
- 同一家公司，对比最早和最晚的分析记录
- 矩阵中"评级趋势"列有明显方向性变化（↗或↘）
- 分析变化背后是"公司基本面变了"还是"你的认知变了"

**输出格式**：
```markdown
### 📈 判断漂移

**万科的评级在悄悄改善**
- 2025-12: ❌ "行业寒冬，不碰"
- 2026-03: ❌ "还在下行，再等等"
- 2026-07: ❌ "龙头低位，但等待信号"

→ 三次都是 ❌，但逻辑从"绝对不碰"变成"等待信号"
→ 你是否在无意识地接近买入点？值得明确设定一个"行业拐点信号清单"
```

### 发现 5：信息盲区 🕳️

**分析方式**：
- 矩阵的行业 vs 申万 31 个一级行业
- 交叉比对 2e 的结果
- 区分：主动回避 vs 潜在盲区

**输出格式**：
```markdown
### 🕳️ 信息盲区

**已覆盖行业 (8/31)**：房地产、白酒、新能源、银行、医药、...

**潜在盲区 (23/31)**：
- 公用事业 - 高股息属性，可能符合你的策略但从未分析
- 有色金属 - 与黄金相关，你关注黄金但没系统分析过有色股
- ...

**建议关注**：公用事业、建筑材料（与房地产关联紧密但未单独分析）
```

## 注意事项

1. **不瞎猜**：每条发现必须引用具体来源（文档路径 + 分析日期），没有证据链的发现不输出。
2. **区分事实和推测**：implicit_premise 是 AI 推断的，需明确标注"AI 推断，请确认"。
3. **控制数量**：每种发现类型最多输出 3 条，避免信息过载。优先输出置信度最高的。
4. **容忍知识库太小**：如果公司日志 < 5 篇，大部分发现不可靠，自动降级为简单的"知识库概览"。
5. **增量 vs 全量**：每周运行只分析"上次洞察报告之后新增/变更的内容"，通过 `.radar-state.json` 中记录的 `last_discover_check` 过滤。
6. **关联补全要小心**：自动补关联之前，确认两个文档确实有实质性关联，不是"刚好打了同一个标签"。
