# 知识雷达 (knowledge-radar)

## 核心定位

不追逐"今天发生了什么"，只关注**什么变了**——而且只关心和你持仓/关注的公司相关的变化。

## 双层架构

```
事件层 🔔（高频差分）              深度层 📊（定时全量）
──────────────────────────       ──────────────────────────
公告变化 → 新公告？有→推送         日检 → 每日盘后汇总
异动提醒 → 涨跌超阈值？有→推送     周检 → 研报 + 行业政策
自选新闻 → 相关新闻出现？有→推送   月检 → 宏观指标
                                 季报检 → 财报三表分析
轻量判断，有变化才出声             需要 AI 深度解读
```

## 触发方式

通过定时任务传入 `mode` 参数区分运行模式：

| mode       | 用途                    |
| ---------- | --------------------- |
| `event`    | 高频差分检查，轻量快速           |
| `daily`    | 每日盘后完整汇总              |
| `weekly`   | 周末深度：研报 + 券商观点 + 行业政策 |
| `monthly`  | 宏观月检：PMI/CPI/社融/利率    |
| `earnings` | 季报深度：财报三表 + 指标趋势对比    |

定时任务的 cron 表达式在 CronCreate 中设置，不在本 Skill 中硬编码。

## 知识锚点

Radar 从 SiYuan 自动读取关注范围（不硬编码在 Skill 中）。**自选股来源：`/投资知识库/自选股`**。

该文档必须包含 A 股 / 港股两个 Markdown 表格，Radar 解析表格中的 `代码` 列，得到纯数字代码（如 `600519`、`0700`），写入 `.radar-state.json` 的 `watchlist`。

```markdown
## A 股

| 名称 | 代码 |
|------|------|
| 贵州茅台 | SH600519 |
| ... | ... |

## 港股

| 名称 | 代码 |
|------|------|
| 腾讯控股 | HK0700 |
| ... | ... |
```

首次运行时若 SiYuan 中尚无 `/投资知识库/自选股`，会提示用户先创建该文档。

## 状态管理

状态文件：`.claude/skills/knowledge-radar/.radar-state.json`

```json
{
  "last_event_check": "2026-07-05T14:00:00",
  "last_daily_check": "2026-07-05",
  "last_weekly_check": "2026-07-01",
  "last_monthly_check": "2026-07-01",
  "watchlist": ["000002", "600519"],
  "watchlist_updated": "2026-07-05"
}
```

每次运行更新对应时间戳。`watchlist` 唯一从 `/投资知识库/自选股` 同步。

## 三大数据源：各有所长，不可互相替代

本 Skill 的三个数据源**不是备选，是互补**。每个都有其他两个做不到的能力。你必须理解为什么不能只用 AI\_Tools 偷懒。

### 灵犀 (gtht-lingxi-unified) — 国泰海通独家

**调用方式**：`Bash` 工具执行 `node skill-entry.js <命令> <参数>`，在 Skill 目录 `~/Downloads/gtht-lingxi-unified/` 下运行。

| 命令           | 独占能力（AI\_Tools / mx-\* 做不到）                                       |
| ------------ | ----------------------------------------------------------------- |
| `marketdata` | 实时行情含**当日资金净流入**，AI\_Tools QueryStockPriceInfo 没有资金流向             |
| `ranklist`   | 12 维度全市场排行，**资金净流入榜** AI\_Tools 没有                                |
| `financial`  | 国泰海通内部财务数据库，自然语言查询，**无需指定指标名**                                    |
| `research`   | **国泰海通研究所独家研报**，AI\_Tools GetStockResearchReport 和 mx-search 都搜不到 |

### mx-\* — 东方财富独家

**调用方式**：`Skill` 工具加载 mx-search / mx-data，然后按 Skill 内的命令行执行。

| Skill                | 独占能力（AI\_Tools / 灵犀 做不到）                                  |
| -------------------- | --------------------------------------------------------- |
| `mx-search`          | **返回资讯/公告/新闻的正文全文**，AI\_Tools GetStockRelatedNews 只返回标题摘要 |
| `mx-data finance`    | **结构化财报数据（xlsx+md）**，AI\_Tools 的财报接口只返回 Markdown 表格       |
| `mx-data macro`      | **结构化宏观数据（CSV）**，AI\_Tools GetAllEconomicData 返回格式不稳定     |
| `mx-data comparable` | **同业公司对比数据**，AI\_Tools 和灵犀都没有此能力                          |

### AI\_Tools MCP — 通用金融数据

**调用方式**：直接调用 MCP 工具。

| 工具                     | 独占能力（mx-\* / 灵犀 做不到）         |
| ---------------------- | ---------------------------- |
| `GetClsTelegraphNews`  | **财联社实时电报**，mx-search 和灵犀都没有 |
| `GetStockChanges`      | **全市场异动扫描**，一次调用覆盖全市场        |
| `GetBrokerOpinion`     | **全市场券商观点汇总**，跨券商聚合          |
| `GetCapitalTideReport` | **资金潮汐六维度分析**，灵犀只有单日资金流向     |

### 关键原则

> **每个数据需求必须用"独占能力匹配"的数据源作为首选，不可用"也有这个功能"的数据源替代。**
>
> 例：搜研报 → 必须用灵犀 research（国泰海通独家），AI\_Tools GetStockResearchReport 只能作为**额外补充**，不能替代。
> 例：搜资讯 → 必须用 mx-search（返回全文），AI\_Tools GetStockRelatedNews 只能作为**额外补充**，不能替代。

## 事件层 🔔 (mode=event)

### 目标

轻量快速检查：有没有和你相关的**新**东西？单次运行控制在 60 秒内（加入了归因步骤）。

### 检查项与数据源

| 检查    | 必须用                                  | 独占原因                  | 可选补充                                |
| ----- | ------------------------------------ | --------------------- | ----------------------------------- |
| 新公告   | `mx-search` 搜索 "{name} 公告"           | 返回公告全文，AI\_Tools 只有标题 | `AI_Tools: GetStockNotice`          |
| 自选股新闻 | `mx-search` 搜索 "{name}"              | 返回新闻正文，AI\_Tools 只有摘要 | —                                   |
| 异动检查  | `灵犀 marketdata` 查实时行情                | 含资金净流入，AI\_Tools 没有   | `AI_Tools: GetDailyKLineData`(算ATR) |
| 连续阴跌  | `AI_Tools: GetDailyKLineData` 取近 5 日 | 灵犀 marketdata 无历史 K 线 | —                                   |
| 财联社电报 | `AI_Tools: GetClsTelegraphNews`      | mx-search 和灵犀都没有实时电报  | —                                   |

### 异动判定：动态阈值

不再用固定 ±5%，而是**每只股票用自己的波动率当尺子**：

```
1. 对每只关注股，拉取近 25 个交易日 K 线（AI_Tools GetDailyKLineData days=25）
2. 计算 20 日 ATR（Average True Range）：
   ATR = MA(max(H-L, |H-C_prev|, |L-C_prev|), 20)
3. 动态阈值 = 2 × ATR / 昨日收盘价 × 100%（即 2 倍 ATR 百分比）
4. 今日涨跌幅 vs 动态阈值 → 超过才触发
```

示例：茅台 20 日 ATR 约 1.2%，则阈值 = 2.4%。今日跌 2.5% 触发。银行股 ATR 0.5%，阈值 = 1%，今日跌 1.2% 就能触发。**每只股票有自己的"异常"标准。**

### 连续阴跌检测

```
1. 从 K 线取近 5 个交易日收盘价
2. 计算最近 3 个交易日累计涨跌幅
3. 累计跌幅 > 8% → 触发"连续阴跌"预警
   （即使每一天单日都没触发动态阈值）
```

这能捕捉到"温水煮青蛙"式下跌——每天跌 2-3%，单日不显眼，三天加起来就很危险。

### 异动归因：四分类

每次异动触发后，**必须追加快速归因**，不满足于"涨了/跌了"：

```
对触发了异动的股票，用 mx-search 搜索当日相关新闻：
  mx-search "{name} 今日涨跌原因"

归为以下四类之一：
```

| 归因类型        | 判断标准                          | 信号含义                                     |
| ----------- | ----------------------------- | ---------------------------------------- |
| **业绩驱动**    | 当天有业绩预告/快报/财报发布，或券商研报大幅调整盈利预测 | 基本面变化，需要进一步分析                            |
| **行业轮动**    | 同行业多只股票同向异动，无个股特有利空/利好        | 板块资金流动，个股基本面未变                           |
| **消息面**     | 有明确公告（重组/增减持/重大合同/政策），或权威媒体报道 | 信息驱动，需判断是短期冲击还是长期影响                      |
| **⚡ 无理由波动** | 以上三类都不匹配，找不到明确驱动因素            | **最值得警惕**——可能是信息不对称（有人比你先知道），也可能是纯粹的市场噪音 |

归因结果写入输出时标注置信度：`高（多源交叉验证）/ 中（单一来源）/ 低（AI推断）`

### 执行流程

```
1. 读取 .radar-state.json → 获取 last_event_check 和 watchlist
2. 同步 watchlist：从 /投资知识库/自选股 读取，若自选股文档有变化则更新
3. 并行执行：
   a. mx-search 搜索每只关注股的公告 + 新闻
   b. 对每只关注股拉 K 线数据 → 计算动态阈值 → 灵犀 marketdata 查当日涨跌 → 比较
   c. K 线计算近 3 日累计跌幅 → 检测连续阴跌
   d. AI_Tools GetClsTelegraphNews 拉电报 → 关键词匹配
4. 过滤：只保留时间 > last_event_check 的结果
5. 对触发了异动的股票 → 执行异动归因（mx-search 搜索原因 → 四分类）
6. 判断：
   → 无新信息：静默结束，不写入 SiYuan
   → 有新信息：写入 /投资知识库/每日发现/YYYY-MM-DD.md
7. 更新 last_event_check
8. 数据源完整性检查（必须执行，不可跳过）：
   ✅ mx-search 已调用？[是/否，搜索了 {N} 只股票]
   ✅ 灵犀 marketdata 已调用？[是/否，查询了 {N} 只股票]
   ✅ AI_Tools 已调用？[是/否，工具: GetClsTelegraphNews, GetDailyKLineData]
   缺失任一项 → 必须补充后再结束，或在输出中明确标注"已尝试但不可用"
```

### mode=earnings：季报深度（预期差驱动）

| 数据需求 | 必须用                            | 独占原因                                  | 可选补充                                               |
| ---- | ------------------------------ | ------------------------------------- | -------------------------------------------------- |
| 财报三表 | `mx-data finance`              | **结构化 xlsx+md**，AI\_Tools 只有 Markdown | `AI_Tools: GetFinancialReport`                     |
| 估值指标 | `灵犀 financial`                 | 自然语言查询，无需指定指标名                        | `AI_Tools: GetFinancialIndicators`                 |
| 一致预期 | `mx-search` 搜索 "{name} 券商一致预期" | **返回全文可提取预测值**                        | `灵犀 research` / `AI_Tools: GetStockResearchReport` |
| 同业对比 | `mx-data comparable`           | AI\_Tools 和灵犀都没有此能力                   | —                                                  |

投资不看绝对值好不好，看的是**和市场一致预期比怎么样**。本模式以"预期差"为核心分析框架。

```
1. 读取 watchlist（从 /投资知识库/自选股）中所有 A 股公司
2. 筛选：仅分析已发布最新季报的公司（财报季分批披露，不是所有公司同时发）
3. 财报数据拉取：
   a. mx-data finance 拉取最新季报：
      python3 scripts/query_data.py --query "{name1}、{name2}...最新财报" --data-type finance --indicators "营收,净利润,ROE,毛利率,净利率,资产负债率,经营现金流,每股收益"
   b. 灵犀 financial 补充查询：
      node skill-entry.js financial "{name} 市盈率 市净率 股息率 营收增速 利润增速"
4. 预期差三维分析（核心）：

   维度一：实际 vs 一致预期
   ─────────────────────────────────
   a. mx-search 搜索 "{name} 券商一致预期 {当前季度}" 
      → 提取券商对营收/净利润的预测均值
   b. 若无法从搜索直接获取一致预期数据，替代方案：
      - 灵犀 research 搜索 "{name} 研报" → 从最新研报中提取盈利预测
      - AI_Tools GetStockResearchReport → 从研报摘要中提取预测
   c. 计算预期差：
      - 营收预期差 = (实际 - 预期) / 预期 × 100%
      - 利润预期差 = (实际 - 预期) / 预期 × 100%
   d. 定性判断：
      → 🟢 超预期：利润超预期 > 5% 且营收也超预期（质量高）
      → 🟡 略超预期：利润超 0-5%，或利润超但营收不及（质量可疑）
      → 🟠 符合预期：±3% 以内
      → 🔴 低于预期：利润低 > 3%，需关注原因
      → ⚠️ 大幅低预期：利润低 > 10%，可能基本面恶化

   维度二：财报后股价反应（市场用脚投票 + 相对大盘）
   ─────────────────────────────────
   a. 确定财报发布日期（从公告中获取）
   b. 拉取财报发布当日及后两日的 K 线（AI_Tools GetDailyKLineData）
   c. 计算：
      - 财报后首日涨跌幅、三日累计涨跌幅（绝对）
      - 财报后三日行业指数涨跌幅（灵犀 ranklist 或 AI_Tools GetIndustryChangeRank）
      - 相对表现 = 个股三日涨跌幅 - 行业指数三日涨跌幅
   d. 绝对涨跌容易被大盘波动干扰，**相对表现为核心判断依据**：
      → 个股+1%，行业+3% → 相对-2%，实际跑输 → 市场并不买账
      → 个股-1%，行业-5% → 相对+4%，实际跑赢 → 抗跌，市场用脚投了信任票
   e. 交叉判断（以相对表现 + 预期差组合）：
      → 超预期 + 相对跑赢 = 市场认可（标准剧本）
      → 超预期 + 相对跑输 = ⚠️ "好消息不涨"——市场在担心什么更深层的问题？
      → 低预期 + 相对跑赢 = ⚡ "利空出尽"或"没想象中那么差"——是否见底信号？
      → 低预期 + 相对跑输 = 市场已在预期内，不意外

   维度三：历史预期管理习惯
   ─────────────────────────────────
   a. 从 SiYuan 公司日志中提取该公司历次财报季的分析记录
   b. 统计该公司历史 beat/miss 模式：
      - 习惯性超预期（连续 3 次以上 beat）→ 市场可能已把"超预期"当做 baseline
      - 习惯性低预期（连续 3 次以上 miss）→ 管理层保守指引？
      - 忽高忽低 → 业绩可预测性差，投资风险更高
   c. 若 SiYuan 中尚无历史记录（首次跟踪），标注"首次跟踪，无历史对比"

5. 逐家分析（标准财务指标）：
   - 营收/利润同比、环比变化
   - ROE、毛利率、净利率趋势（最近 4-8 个季度）
   - 现金流 vs 净利润质量（经营现金流/净利润 > 0.8 为健康）
   - 资产负债率变化
   - 与行业均值对比（mx-data comparable）

6. 综合判断：
   结合预期差 + 股价反应 + 历史习惯 + 财务趋势 → 给出综合评估
   → 🟢 超预期且质量高 → 追加公司日志 ✅
   → 🔴 低预期且趋势恶化 → 追加公司日志 ⚠️ + 风险跟踪
   → ⚡ 预期差信号矛盾（如数字好但股价跌）→ 重点标注，需人工判断

7. 写入 /投资知识库/每日发现/YYYY-Q{N}-季报分析.md
   同步更新每家公司日志（追加财报季分析记录）
8. 数据源完整性检查（必须执行）：
   ✅ mx-data finance 已调用？[是/否，拉取了 {N} 家公司]
   ✅ 灵犀 financial 已调用？[是/否，查询了 {N} 家公司]
   ✅ mx-search 已调用？[是/否，搜索了 {N} 家公司的预期差]
   ✅ mx-data comparable 已调用？[是/否/不适用（同行业<3家）]
   缺失任一项 → 必须补充后再结束
```

## 状态更新规则

每次运行结束时：

1. 更新 `.radar-state.json` 中对应的时间戳
2. event 模式：更新 `last_event_check`
3. daily/weekly/monthly：更新对应字段
4. 如果 `/投资知识库/自选股` 内容有变化（新增/删除/代码变更），同步更新 `watchlist` 并记录 `watchlist_updated`

## 注意事项

1. **数据源完整性检查是硬性要求**：每个 mode 末尾的"数据源完整性检查"必须执行，不可跳过。缺失的必须标注原因（"已尝试但不可用"），不能静默跳过。
2. **event 模式要快**：不写长篇分析，只记录"什么变了"。单次运行控制在 60 秒内（加入了归因步骤需要额外搜索时间）。
3. **不重复写入**：同一天的 event 和 daily 写同一个文件，daily 覆盖 event 临时记录。
4. **静默优先**：event 模式没有新发现就不写 SiYuan，避免信息过载。
5. **数据源容错**：某个数据源挂了不影响其他检查项，在输出中标注"XX 数据源不可用，已跳过"。
6. **非交易日跳过**：周末和节假日不执行 event 和 daily 模式（通过灵犀 marketdata 或 AI\_Tools GetAStockIndexes 判断当天是否有行情数据）。
7. **每项发现标注数据来源**：`📊 来源: 灵犀 research` / `mx-search` / `财联社电报`，方便追溯。
